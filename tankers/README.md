# Kuwaiti Oil Tankers — database and dataset

A fleet register for the **Kuwait Oil Tanker Company (KOTC)** — ناقلات النفط الكويتية —
the tanker arm of Kuwait Petroleum Corporation, published as both a flat dataset (CSV
and JSON) and a relational database (SQL schema, seed and worked queries), with a
browsable page at [`index.html`](index.html).

KOTC owns and manages the ships that move Kuwait's crude oil, refined products and
LPG. Its fleet stands at roughly thirty vessels after a phased renewal programme that
ran from the mid-2000s to 2021.

## What is real and what is not

This matters more than anything else here, so it comes first.

| Table | Rows | Status |
|---|---|---|
| `vessels` | 30 | **Real.** Compiled from the sources listed below. |
| `ports` | 24 | **Real** ports; coordinates and sea distances are **approximate**. |
| `cargo_types` | 11 | **Real** grades; assay figures are **nominal** and vary by cargo. |
| `builders` | 7 | **Real**, derived from `vessels`. |
| `voyages` | 1,167 | **SYNTHETIC.** Generated. No row describes a real shipment. |

`voyages` exists so the register can be *queried as a fleet* rather than read as a
list — joins, aggregates, tonne-miles, trade-lane analysis. It is generated by
`build.py` from a fixed seed, and every row carries `data_source = 'synthetic'` so the
label survives into any query result. **Do not cite it as a record of KOTC's trade.**

Three further caveats on the real data:

- **Deadweight.** Where a figure was published for that specific hull, `dwt_basis` is
  `reported`. Where it is carried across from a confirmed sister ship in the same
  series, it is `sister_vessel_class`. Ten of the thirty rows are the latter.
- **Flags.** Four vessels (`status = 'flag_unverified'`) carry an AIS MMSI from a
  registry that does not match the recorded flag — Bahamas, Panama and St Kitts and
  Nevis series. They may have been sold or reflagged. Query 6 in `queries.sql` lists them.
- **Arabic names.** `name_ar` gives the Kuwaiti place name each ship is named for.
  These are transliterated back from the English and have **not** been checked against
  KOTC's own Arabic-language material. Treat them as a convenience, not a source.

Compiled September 2026. The fleet changes; re-check before relying on it.

## Files

```
tankers/
├── README.md                     this file
├── schema.sql                    DDL: 5 tables, 3 views, keys, indexes, constraints
├── seed.sql                      generated INSERTs for every table
├── queries.sql                   11 worked analysis queries
├── build.py                      validates the sources, generates everything else
├── index.html  styles.css  app.js  the browsable page
└── data/
    ├── vessels.csv       ← hand-curated source
    ├── ports.csv         ← hand-curated source
    ├── cargo_types.csv   ← hand-curated source
    ├── builders.csv              derived
    ├── voyages_synthetic.csv     generated
    ├── *.json                    a JSON mirror of each table
    └── fleet.json                one bundle the page loads
```

The three `← hand-curated source` files are the only ones edited by hand. Everything
else is rebuilt from them:

```sh
python3 tankers/build.py
```

No third-party packages. `build.py` validates the sources against the schema's
constraints first and refuses to write anything if a check fails.

## Loading the database

SQLite:

```sh
sqlite3 kotc.db < tankers/schema.sql
sqlite3 kotc.db < tankers/seed.sql
sqlite3 kotc.db < tankers/queries.sql
```

PostgreSQL:

```sh
createdb kotc
psql kotc -f tankers/schema.sql -f tankers/seed.sql
```

The DDL is written to run unchanged on both (SQLite 3.25+, PostgreSQL 12+). Two
queries in `queries.sql` carry an inline comment where the dialects differ
(`GROUP_CONCAT` / `STRING_AGG`, `SUBSTR` / `EXTRACT`).

On SQLite, `PRAGMA foreign_keys = ON;` before loading — it is off by default, and the
foreign keys are the point.

Pandas, straight from the CSVs:

```python
import pandas as pd
vessels = pd.read_csv("tankers/data/vessels.csv")
voyages = pd.read_csv("tankers/data/voyages_synthetic.csv", parse_dates=["departure_date", "arrival_date"])
vessels.groupby("vessel_type")["dwt"].agg(["count", "sum"])
```

## Data dictionary

### `vessels` — the fleet register

| Column | Type | Notes |
|---|---|---|
| `vessel_id` | text, PK | Slug of the vessel name. |
| `name`, `name_ar` | text | English name; Arabic place name (unverified — see above). |
| `imo` | int, unique | IMO number. Permanent to the hull; survives renaming and reflagging. |
| `mmsi` | int | AIS identity. Tied to the *current* registration, so it changes on reflagging. |
| `call_sign` | text | Where known. Kuwaiti call signs begin `9K`. |
| `vessel_type` | text | `VLCC`, `Aframax`, `MR Product Tanker`, `VLGC`, `LPG Carrier`, `Bunker Vessel`. |
| `cargo_class` | text | `crude`, `products`, `lpg`, `bunkers`. |
| `dwt` | int | Summer deadweight, tonnes. |
| `dwt_basis` | text | `reported` or `sister_vessel_class`. NULL exactly when `dwt` is NULL. |
| `capacity_cbm` | int | Cubic capacity. Gas carriers only — enforced by a CHECK. |
| `loa_m`, `beam_m` | real | Length overall and beam, metres. |
| `built_year` | int | Year of delivery. |
| `builder_id` | text, FK | → `builders`. |
| `builder`, `builder_country` | text | Kept denormalised alongside the FK for readability. |
| `flag` | text | Flag state of registry. |
| `operator` | text | `KOTC` throughout. |
| `status` | text | `in_service`, `flag_unverified`, `laid_up`, `sold`, `scrapped`. |
| `notes` | text | Delivery dates, programme phase, and why a row is uncertain. |

### `ports`

| Column | Type | Notes |
|---|---|---|
| `port_id` | text, PK | |
| `name`, `name_ar` | text | Arabic given for the Kuwaiti and Egyptian ports only. |
| `country`, `country_iso2`, `region` | text | |
| `latitude`, `longitude` | real | **Approximate** anchor for the port area, not a berth. |
| `role` | text | `load` (the five Kuwaiti terminals), `discharge`, `bunker`. |
| `sea_distance_from_ahmadi_nm` | int | **Approximate** routeing distance from Mina Al-Ahmadi. Not a published distance table. Rotterdam is routed via Suez, Houston via the Cape. |

### `cargo_types`

| Column | Type | Notes |
|---|---|---|
| `cargo_code` | text, PK | `KEC`, `KHAFJI`, `GASOIL`, `PROPANE` … |
| `category` | text | `crude`, `product`, `lpg`. |
| `api_gravity`, `sulphur_pct` | real | **Nominal** assay values for the crude grades; published figures vary between cargoes. NULL for products and gases. |

### `voyages` — synthetic

| Column | Type | Notes |
|---|---|---|
| `voyage_id` | text, PK | `V-<year>-<seq>`. |
| `vessel_id`, `load_port_id`, `discharge_port_id`, `cargo_code` | text, FK | |
| `departure_date`, `arrival_date` | date | 2023-01-01 to 2025-12-31. |
| `sea_days`, `distance_nm`, `laden_speed_knots` | | Laden leg only. |
| `cargo_tonnes` | int | 90–97% of deadweight. |
| `freight_rate_ws` | real | Worldscale points, the tanker market's rate unit. |
| `data_source` | text | Always `synthetic`. Constrained to that one value. |

### Views

- `v_fleet_summary` — hulls, deadweight and average age by type. Real data only.
- `v_vessel_utilisation` — voyages, tonnes and sea days per ship. Touches `voyages`.
- `v_trade_lanes` — voyages and tonnes by load/discharge pair. Touches `voyages`.

## How the voyages are generated

`build.py` walks each ship through 2023–2025 one round trip at a time: pick a
discharge port weighted by vessel type (VLCCs run the long hauls to China, Korea,
Japan and North West Europe; MRs stay regional around Fujairah, Pakistan, India and
East Africa; VLGCs follow the Asian LPG trade), pick a Kuwaiti terminal and a cargo
grade that suit the ship's class, sail at 11.8–15.2 knots, load to 90–97% of
deadweight, discharge over 2–5 days, ballast home, and load again over 2–4 days.
First sailings are staggered so the fleet is not in step.

The RNG is seeded with `SEED = 20260915`, so the same source tables always produce the
same 1,167 voyages. Change the seed or the source CSVs and re-run to get a different
set.

## Sources

The vessel rows were compiled from public reporting and AIS-derived vessel registries,
September 2026:

- Kuwait Oil Tanker Company, company and fleet pages — <https://www.kotc.com.kw/>
- Wikipedia, *Kuwait Oil Tanker Company* — fleet composition and VLCC delivery years
- VesselFinder, MarineTraffic, MyShipTracking, MaritimeOptima, vesseltracker,
  MagicPort, TrustedDocks — IMO and MMSI numbers, build years, deadweight, dimensions
- gCaptain, *DSME Delivers Al Kout to Kuwait Oil Tanker Company*
- MarineLink, *Great Ships of 2014: Al Kout* — Phase III programme and 317,300 dwt
- The Maritime Standard, *KOTC expands product tanker fleet* — the 2018 Hyundai Mipo
  order and the three 82,500 m³ VLGCs
- Egypt Oil & Gas / Kuwait Times / LogisticsGulf — Al-Yamamah and Shegardiah deliveries
- VesselFinder news, *KOTC takes delivery of Al-Siddeeq*
- Kuwait National Petroleum Company — refinery and terminal capacities
- Ports directories (marinelink, findaport) — Mina Al-Ahmadi berth structure

Where two sources disagreed, the row keeps the figure that more of them agreed on and
`notes` records the conflict.
